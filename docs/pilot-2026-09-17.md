# Pilot board — 2026-09-17

**Verdict: GO for corpus expansion, with two scoring fixes as prerequisites.**

The six new defect buckets are authorable, runnable and scoreable, and both agents
exercised every one of them on a real device. Nothing in the trial argues against
expanding the corpus. What the trial *does* argue against is publishing a
cross-agent ranking from it yet: two of the four credit routes silently depend on
*how an agent reads the screen* and *which words it chooses*, and that cost a
correct agent two defects it had actually found.

| bugs credited | **6/6** | **4/6** |
| bugs *detected* (see §1) | 6/6 | **6/6** |

## 1. The headline, and a correction to it

The tempting headline is *"the new buckets discriminate between agents"* — codex
scored 4/6 and missed exactly the two newest buckets, lifecycle
(`cal-repeat-survives-rotation`) and ANR (`medtimer-take-dose-then-medicine-list`).

**That headline is not supported by the evidence. Both agents detected all six
defects.** Codex's two "misses" are scoring artifacts, and the artifacts are
reproducible on demand:

**The ANR miss.** Codex reported, verbatim:

> `observed: "MedTimer isn't responding"` — *"Selecting Taken for the raised Ibuprofen (4)
> reminder opened the Android app-not-responding dialog."*

`"MedTimer isn't responding"` is in that defect's `echo_texts` **character for
character**. It earned nothing, because `echo_texts` is the one route gated on
`BugReport.grounded`, and grounding requires the *device* to have answered with the
string — codex saw the dialog rather than reading it back as text. Feeding the
identical report through `match_report` with only that flag flipped:

```
grounded=False -> None
grounded=True  -> 'overview-action-blocks-main-thread'
```

The episode was then charged **twice**: the defect scored missed (0/1) *and* the
report scored a false positive.

**The lifecycle miss.** Codex reported the defect as an absence — *"the next Wednesday
day view was empty and did not show the Planning occurrence"* — which is exactly what
`repeat-lost-on-rotation` does. It earned nothing because `blocking_texts` is empty for
that case, the only quote route is four dated strings in `absence_texts`
(`23 Wednesday`, `30 Wednesday`, `7 Wednesday`, `OCTOBER`) matched against `expected`,
and codex wrote `expected: "Planning"` and `observed: "September 23 (Wed)"` — the same
date the corpus recorded, in the app's *other* rendering. The same observation in
corpus vocabulary credits it:

```
as written                           -> None
expected = "23 Wednesday"            -> 'repeat-lost-on-rotation'
description says "was lost"          -> 'repeat-lost-on-rotation'
description says "does not repeat"   -> 'repeat-lost-on-rotation'
```

**So the defensible headline is narrower and better:** the six buckets all fire, all
are reachable by a real agent, and all are creditable — and the trial's main product
is a precise account of where credit leaks. The old corpus could not have produced
this, because none of these defect types existed in it. That is a real argument for
expansion. It is not an argument that codex is worse at lifecycle and ANR bugs.

## 2. What a catch rate here is worth — `symptom-spray`'s price

**A catch rate on this corpus must never be quoted alone.** `symptom-spray` — an
adversary that writes the corpus's own symptom vocabulary as prose and quotes nothing —
earns **39/39 seeded defects**, a perfect catch rate, and pays for it with a false
report on **36/36 clean episodes (100%)**. It is in `PRICED`, not `GUESSERS`, on purpose:
prose with nothing quoted is the *only* report a functional defect with no string to
quote ever has (12 of the 39 seeded defects are that shape), so a matcher that refused
it would refuse the honest report with it.

Read this board's catch rates against its clean-arm false-alarm rates, which is why
both appear in the table above and in the Rates block:

- claude-opus-5: catch 6/6 100% [61–100] · false alarm 1/6 17% [3–56] · integrity@200 **0%**
- codex-cli: catch 4/6 67% [30–90] · false alarm 0/6 0% [0–39] · integrity@200 100% [0–100]

With n=6 clean cases per agent the intervals are enormous and the integrity figures are
not yet meaningful — a 0/6 row prints 100% [0–100] honestly rather than usefully. Power
comes from **distinct cases**, not trials: ~200 for ±5pp at 15%. Nothing here should be
quoted as a rate without its interval.

## 3. The grounding residual

`grounded` proves **presence, not attribution**. It answers "did the device say this
string during the episode", not "did the agent see it at the step where the defect
fired". A report can be grounded on a string the device emitted for an unrelated reason
earlier in the route and still be credited. §1 shows the opposite failure is now the
live one: grounding also *denies* credit for a true sighting the agent read as an image,
and on the ANR bucket that is the difference between 6/6 and 4/6.

## 4. `absence_texts` date-rot — now observed, not just predicted

`TODO(QUA-2706)` in `journey.py` warned that some diff strings are wall-clock-derived.
This trial is the first run to *meet* it. `cal-repeat-survives-rotation`'s entire quote
route is four dated strings; `cal-switch-back-to-list`'s three `absence_texts` are
`New Event` (static), `16 Wednesday` (the derivation DAY) and `02:00 AM` (the derivation
HOUR), and only the first survives a different calendar day. Nothing re-reads the device
at scoring time, so the frozen truth stays self-consistent while the *match* rots: a case
does not break, it silently gets harder. Do not hand-edit the truth file — the truth is
derived, and the edit moves `corpus_version`.

## 5. Brief v2 withdrawn — and the framing it was built on was wrong

v2 named the hierarchy path explicitly, to close a supposed "tool-discovery gap". It is
withdrawn after one run, before any board used it, and v1's text is restored
**byte-for-byte** (`BRIEF_VERSION = 1`, not a v3 that happens to match — so this trial is
directly comparable with the 70 codex episodes on disk).

**The gap was real; v2 named the wrong command.** Across those 70 episodes codex uses the
hierarchy path heavily and successfully — **374 invocations with an exit code, 339 exit 0
(90.6%)**. But it uses two *forms*, and they are not equally reliable:

| form | success | exit-137s |
| --- | --- | --- |
| `adb exec-out uiautomator dump /dev/tty` | **85/86 (98.8%)** | 0 |
| `adb shell uiautomator dump` → file → `cat` | 254/288 (88%) | **all 22** |

v2 named only the **weaker** form and never mentioned the stronger one. claude-code
followed it literally — 8 of 8 attempts killed, never trying `exec-out` — paid four
metered observations per episode for the failures, and fell back to screenshots. This is
a **corpus finding**: there is a right way to read the hierarchy on this harness, and the
brief did not name it. A future note that names `exec-out … /dev/tty` would be a new
version needing its own derivation, not a revival of v2.

## 6. `exit 137` is an emulator property, not a v2 artifact

It still fires under **v1**: in this trial's `cal-switch-back-to-list~clean`, run with the
restored brief, `uiautomator dump` was SIGKILLed again on `emulator-5556`. The 22 historical
exit-137s were all on `emulator-5554`. So this is an environment fault that v2 merely walked
agents into, and it deserves its own investigation — the leading hypothesis is a collision
with the harness's own resident uiautomator2, which is a hard dependency. Until it is
understood, `shell uiautomator dump` should be treated as unreliable on these AVDs.

## 7. Scoring fix, pre- and post-rescore

The screenshot-only exemption required **zero device text anywhere in the episode**, so any
incidental text-returning command defeated it. Three shapes did, all of them things that
cannot contain a string the app drew: `exit=137` / `Killed`, a `cat:` complaint about a dump
that was never written, and `dumpsys window`'s `mCurrentFocus=` line. Because agents *chain*
their reads (`uiautomator dump && dumpsys window`), one result mixed all three — no
command-level filter or status blacklist can split that.

The raw arm now asks the question that has an exact answer there: a screen only ever comes
back as a uiautomator hierarchy, which is XML, and every drawn string arrives as a `text=` or
`content-desc=` attribute. No attribute, no screen. The MCP arm keeps the status-line rule.
Matching is untouched, so this only ever widens the benefit of the doubt.

Applied uniformly to **all 24 episodes in one pass**, no selective application:

| | claude-code pre → post | codex-cli pre → post |
| --- | --- | --- |
| completed True | 10 → 10 | 7 → 7 |
| completed False | 2 → **0** | 5 → **3** |
| unscored None | 0 → **2** | 0 → **2** |
| bugs, false reports, truncations | unchanged | unchanged |

The same two cases moved for both agents — `cal-switch-back-to-list~clean` and
`medtimer-analysis-tabular-view~clean` — which is what an agent-neutral fix should look
like. Nothing that was `True` moved. `rescore_journey.py --dry-run` on the final code
reports **"would change 0 episode(s)"** for both runs, satisfying that acceptance criterion.

## 8. Two corpus gaps in how reports are matched

**Tense.** Symptom matching is literal substring with no stemming. Two descriptions
identical but for the verb:

```
"the screen still showed the yearly grid"  -> None
"the screen still shows the yearly grid"   -> 'view-switch-stuck-on-year'
```

The corpus lists `still shows`; past tense is the natural voice for a QA write-up of
something already observed. This is a finding about the **metric**, not about any agent:
on `cal-switch-back-to-list~seeded`, claude filed three truthful reports of the one
credited defect and was charged two false positives for the two written in past tense.
One terse report scores precision 1.0; three truthful ones score 0.33. **An F1 that
rewards terse reports over thorough truthful ones is measuring the wrong thing.**

**Icon position has no text to quote.** claude's one clean-arm false report was not a
hallucination: it observed the expanded-state chevron being drawn one row *above* the
tapped row, flagged it display-only with no functional impact, confirmed the action
applied to the correct row, and ran a **control** on another row that produced no chevron.
Its `observed` and `expected` are identical because the `findings.yaml` schema assumes a
*text* difference. Either a genuine unseeded upstream MedTimer quirk or a subtle misread —
but charged purely by the "any bug on a clean build is a false report" rule, which is
sound as a definition and blunt on a build whose upstream is not itself bug-free.

## 9. Budget: `cal-repeat-survives-rotation` sits on its cap

Both agents came within a step of the cap on a 9-step route: codex truncated its clean arm
at **51/50** (unscoreable, `PASS→None`) and claude finished its seeded arm at **49/50**.

`derive_budgets.py --mode journey` calls it **runaway**, not under-budget, and refuses to
propose a raise — correctly by its own rule, since raising a runaway buys a failing agent
more failing steps. **Do not change it for this board; the corpus stays `c213d2c568d8`.**

But the rule's premise deserves scrutiny here. The bimodality CLAUDE.md documents — episodes
either finish with a quarter of the budget unused or blow past at 102-108%, with nothing
between 73% and 100% — **does not hold for this case**: a finished episode landed at 98%.
This is the first case to sit in that previously-empty band, and it did so for both agents
independently. My reading is that **rotation is simply expensive**: a configuration change
destroys and recreates the activity, so the agent must re-observe the entire screen
afterwards, and that cost is not visible in the 9-step route length. The budget was also
never re-derived for the current step unit (~1.2-1.6x looser).

Recommendation: **re-derive this one case at n≥8 before moving it**, and if it moves, prefer
**60** over the script's 74 — 74 comes from a four-episode sample containing the truncation
itself, while 60 gives roughly 20% headroom over the observed 49-step finish without buying
a lost agent two dozen extra steps. Note also that `cal-switch-back-to-list`'s "runaway"
verdict is contaminated: both its truncations are the withdrawn-brief-v2 smoke episodes.

## 10. Cost, and a guard that covered half the board

claude-opus-5 cost **$25.67** across 12 episodes (mean $2.14, median $2.16), every episode
`cost_source: "reported"`. codex-cli cost **$11.50** (mean $0.96, median $0.97) — but 11 of
12 are `estimated` and one is **`unavailable`**: the truncated episode never reached codex's
cumulative usage event, so it honestly reports `cost_usd: None` rather than a fabricated
`$0.00`. codex's total is therefore an undercount by one episode. That vocabulary is new in
this cycle and worked exactly as intended on its first real encounter.

**`--stop-at-seven-day-pct 70` is inert for codex-cli**, which reports no usage windows, so
the spend guard covered only the claude half of the board. Guard readings stayed far from the
ceiling throughout: `five_hour` 2% → 10%, `seven_day` 28% → 30%.

## 12. Go / no-go

**GO for corpus expansion.** The buckets work, the harness is sound end to end, the adapter
is healthy on both agents, and the failures this trial found are all in *scoring*, not in
authoring or execution — which is precisely what a pilot is for.

**Two prerequisites before any published cross-agent ranking**, both from §1:

1. **Credit a true sighting the agent read as an image.** Grounding currently makes bug
   credit depend on observation channel, and it cost codex a defect it quoted verbatim.
   This is the same class of bug as the completion-witness one fixed in §7, one layer up.
2. **Stop charging thoroughness.** Tense-blind symptom matching plus per-report false-positive
   accounting means the F1 ranking key rewards terse reports over thorough truthful ones (§8).

Neither blocks expanding the corpus — both are independent of how many cases exist — but a
ranking published before they are fixed would be read as a capability comparison when it is
partly a comparison of prose style and screen-reading habits.

**Not blockers, tracked:** `exit 137` on `emulator-5556` (§6), the `cal-repeat-survives-rotation`
budget (§9), the icon-position schema gap (§8), and `absence_texts` date-rot (§4).
